Passlet can now forward your Mac's SSH agent to a paired Agent on demand, so remote shells and sudo can use your keys without a persistent SSH tunnel. Passlet holds no SSH private keys, and the upstream agent keeps control over which keys are available and whether signing requires Touch ID.

- Run `passlet ssh-agent` on a Linux Agent, or enable `programs.passlet.sshAgent.enable` in Home Manager for a systemd socket that starts Passlet only when a client connects. Point `SSH_AUTH_SOCK` at `~/.local/share/passlet/ssh-agent.sock`.
- Configure the upstream socket on the Approver Mac with `ssh_agent_socket` in `approver.toml`, or `programs.passlet.service.sshAgentSocket` in Home Manager. Forwarding stays disabled until this is set.
- Only key listing and signing are forwarded. Adding or removing keys, locking, and agent extensions are refused. Every request is checked against the Agent's pairing before and after it reaches the upstream agent, so revoking an Agent blocks it immediately.
- Works with `security.pam.sshAgentAuth` on NixOS, so `sudo` in a remote shell authenticates through your Mac's SSH agent.
- Healthy Tailscale listener output in `passlet approver doctor` no longer repeats the pairing instructions.

Upgrade both the Approver and its Agents. Existing pairings are preserved and no migration is needed. See the [SSH-agent forwarding setup](https://github.com/ParetoSecurity/passlet/blob/v0.8.0/docs/SETUP.md#ssh-agent-forwarding).
