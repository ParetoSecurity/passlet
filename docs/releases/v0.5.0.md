Passlet now pairs Agents with their Approver using Ed25519 keys. Every connection is authenticated and encrypted, including local and SSH-forwarded sockets. Approval prompts identify the Agent by its trusted key label, and captured traffic cannot be replayed to request access. Each credential request still requires Touch ID.

- Missing private keys are generated automatically using Go’s standard library. Public keys are exported for pairing, and existing private keys are preserved.
- Home Manager can declare Agent endpoints, trusted public keys, and private-key paths. Private keys stay outside the Nix store.
- Local and SSH Agents share one socket. Tailscale forwards encrypted traffic through loopback, avoiding the GUI app’s restrictions on Unix sockets.
- Doctor reports the Passlet version, explains pairing and Tailscale failures, and includes an issue-reporting link on errors.

Upgrading from v0.4.x requires updating both the Approver and its Agents and configuring pairing, including for Agents on the same Mac. Remove `ssh` from `approver.toml` or `programs.passlet.service.ssh` from Home Manager, and point SSH forwards at the shared `passlet.sock`. If port 17400 has an existing Passlet HTTPS proxy, remove that route before enabling the new TCP forwarding. See the [pairing and migration instructions](https://github.com/ParetoSecurity/passlet/blob/v0.5.0/docs/SETUP.md#pair-agents) and [Tailscale setup](https://github.com/ParetoSecurity/passlet/blob/v0.5.0/docs/SETUP.md#tailscale).
